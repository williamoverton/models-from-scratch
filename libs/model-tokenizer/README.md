# Model tokenizer

A shared, dependency-free byte-level BPE (byte-pair encoding) tokenizer for the
repository's text models. Each model trains its own vocabulary and chooses its
own control tokens.

## Train the TinyStories tokenizer

From the repository root:

```bash
uv run --package model-tokenizer python scripts/train-simple-english-tokenizer.py
```

The script reads the full TinyStories V2 training split from
`/mnt/StorageBox/datasets/TinyStories/TinyStoriesV2-GPT4-train.txt`. It streams
complete stories rather than loading the whole corpus into memory, excluding
the dataset's `<|endoftext|>` separator lines from ordinary-text training.
Validation text is not used.

The vocabulary target is **2,048 total tokens**, including the 256 base bytes
and the single registered control token, `<END_OF_DOCUMENT>`. Future model-data
formatting should explicitly insert that control ID after each story.

The script reports story counts and training time, saves and reloads
`trained-models/tokenizers/simple-english.json`, and prints the tokenization of
a short example with and without the document boundary. Re-running replaces
that artifact. Dataset location, vocabulary target, and output path are constants
near the top of the script.

## Train and save a tokenizer

```python
from model_tokenizer import Tokenizer, train_tokenizer

# Use training documents only; keep validation text held out.
tokenizer = train_tokenizer(
    ["Your training text here."],
    vocab_size=1024,
    control_tokens=["<END>"],
)

ids = tokenizer.encode("Your text.")
ids.append(tokenizer.control_token_ids["<END>"])
print(tokenizer.decode(ids))
print(tokenizer.decode(ids, skip_control_tokens=True))

tokenizer.save("trained-models/tokenizers/example.json")
loaded = Tokenizer.load("trained-models/tokenizers/example.json")
```

`train_tokenizer()` accepts an iterable of text documents. Its vocabulary-size
target includes all 256 base bytes, learned merges, and registered control
tokens. Training stops below the target if no eligible pairs remain. Use the
actual `tokenizer.vocab_size`, not the requested target, to size a model's
embedding and output layers.

## Control tokens

Pass an ordered list of unique, non-empty spellings when training. Controls
receive consecutive IDs after the actual learned byte vocabulary, in registration
order. Look up their IDs in `tokenizer.control_token_ids` and insert them
explicitly when formatting model inputs.

Ordinary `encode()` never recognizes control spellings. For example, encoding
`"What does <END> mean?"` produces ordinary text tokens, not an end marker.

`decode()` displays registered control spellings by default.
`skip_control_tokens=True` omits control IDs but preserves literal spellings
encoded as ordinary text. Decoded text is for display, not lossless serialization
of token IDs: a control and ordinary text can display the same spelling.

## Byte encoding and merge boundaries

All 256 base bytes remain available for unseen text. Pre-tokenization preserves
the text while separating words, whitespace runs, and punctuation runs, and
isolating each numeric character. Merge rules never cross those boundaries.
Non-ASCII numeric characters may still need multiple byte tokens.

Decoding joins bytes before decoding UTF-8, because a token may contain only part
of a character. Invalid generated byte sequences display replacement characters.

Training weights unique chunks by occurrence frequency and updates an index of
pairs after each merge. Equal-frequency pairs are resolved by their first
occurrence in the training input, so document order affects the learned merges.

## Fixed vocabulary and artifacts

Vocabulary bytes, ordered merges, and control IDs are read-only after training.
Loading a tokenizer never adds tokens. Each model owns its tokenizer artifact
and must keep it aligned with its embedding and output matrices.

Versioned JSON artifacts store vocabulary bytes, merges, control IDs, and the
pre-tokenization identity. Loading validates these fields and rejects incompatible
formats or inconsistent IDs. Saving atomically replaces the destination file.

## Use from another workspace package

Add `model-tokenizer` to the consumer's `project.dependencies` and declare its
workspace source in that package's `pyproject.toml`:

```toml
[tool.uv.sources]
model-tokenizer = { workspace = true }
```

See the [development guide](../../DEVELOMENT.md) for workspace setup and the
[design decision](../../design-log/2026-11-13-shared-byte-bpe-tokenizer.md) for
rationale.
